## Current Status (as of 2026-10-02)

🟢 **Every main feature from the README now works end to end, for free, with no AI and no API keys.**

- **Skills:** add, rename, merge or delete skills, with a "did you mean?" check for look-alikes. Teach them nicknames.
- **Proof:** claim a skill and prove it with evidence. Evidence can come from a project, job or school on **My Profile**, and can be edited, unlinked or deleted. A claim can be removed too (your evidence is kept). A skill can never be "Verified" without proof, whether you're adding things or removing them.
- **Job postings:** paste a posting, and the free skill-list reader finds your saved skills in it. Optionally, a free local AI (Ollama) also spots skills you haven't saved yet. Compare it against your proof and see your gaps. Revisit, re-compare, look for newly saved skills, remove a wrong requirement (it stays removed), or delete it. Track your application for each job (saved, applied, interviewing, offer, rejected, withdrawn) with the date you applied, a note, and your next interview time. The Dashboard's "Coming up" box lists interviews in the next two weeks with a link to each prep sheet and an "Add to calendar" button.
- **Learning:** each gap has YouTube search buttons and your own saved links, and the Dashboard ranks which skills to learn first, putting the skills your live applications need at the top. Each skill has a four-step "Your path" checklist showing the next step. Track "studying / finished", which never counts as proof.
- **CV:** upload a PDF, Word or text CV to mark which skills are on it, and see other common skills it mentions that you haven't saved yet, each with an Add button. See CV status and advice next to every gap.
- **CV-first start:** "Add all my CV skills" saves everything your CV lists (as provisional, never verified), and each job shows a match % with what's missing first, plus videos to learn it.
- **Profile autofill:** "Fill from my CV" on My Profile pre-fills draft projects, jobs and education from your CV for you to check and save.
- **Assistant (RAG, learning in stages):** ask questions about your own skills, proof, jobs and gaps; answers come from your data with numbered sources. Guide: `docs/RAG_GUIDE.md`.
- **Backup:** "Download my data" on My Profile saves everything the app stores for you into one file, and "Restore from backup" loads it back into an empty app.
- **Interviews:** a printable prep sheet per job says what you can honestly claim, which proof to talk about, and what not to bluff.

**Environment blocker resolved — for good, not just for now.** `psycopg2` was being blocked by Windows Smart App Control (confirmed via the Windows Code Integrity event log). The project switched database drivers permanently to `pg8000`, a pure-Python driver with no compiled file for Windows to block. Full detail in `HANDOFF.md` §9.

**Housekeeping:** since 2026-10-01 the workflow lives in the repo-root `CLAUDE.md`: every task gets its own commit, and nothing is pushed unless the user asks.

## Working Conventions (full detail lives in `HANDOFF.md`)

- **Learning-first process for every task:** explain the concept, why it's needed, where it fits architecturally, the data flow, and the key design decision — *before* writing code. Then implement, then verify. One task at a time; stop and wait for approval before starting the next.
- **Service layer rule:** plain functions that take a database `Session`, never commit (only flush) — the caller (a route, or a test) owns the transaction and decides when to commit.
- **API layer rule:** routes stay thin, call a service, and commit after success. Domain errors are never caught in a route — one shared handler maps them to HTTP status codes.
- **No `user_id` ever appears in a request.** The single hardcoded user is resolved automatically via a dependency.
- **Verification habit:** after building something, deliberately break the one guarantee that matters most (e.g. remove a safety check), confirm the *right* test fails, then restore the file byte-for-byte and confirm the suite is green again.
- **Live-check habit:** after any task that touches the API, start the real server against the real local Postgres database, exercise the new endpoints for real, then delete exactly what was created so the database is left exactly as it was found.
